planning-with-files 스킬을 써서 다음을 수행해줘.

_NeoStudioHubApp/NeoCAST 프로젝트에 기능을 추가한다.
1) 시스템 전체의 UI를 바꾼다.
   - Zoom과 동일하게 화면의 아래쪽의 컨트롤 바를 만들어 각종 컨트롤 뱃지가 있고, 오른쪽에는 메시지, 페이지 네비게이션, 참가자 상세 등의 패널을 둔다.
   - 아래쪽의 컨트롤 바에는, 마이크(ON/OFF), PenStream(ON/OFF), PDF 업로드(아래의 4번 기능), 참가자(푸시하면 오른쪽에 참가자 보여주기), Chat(푸시하면 오른쪽에 채팅 패널), 메신저(푸시하면 메신저 창이 팝업으로 뜬다), Settings(설정), More(...), Leave(나가기) 버튼이 있다.
   - 각 버튼에서 마이크를 제외하고 나면 현재 구현된 기능을 연결한다. Chat은 아래에서 기능 추가로 설명하겠다.
   - 참고되는 UI 디자인은 https://help.prevail.ai/session-applications/zoom/zoom-overview/ 에서 찾아볼 수 있다.
   - 화면 상단의 편집, 지우기, 종이크기, 펜연결관련의 항목은 그대로 둔다.

2) 채팅
   - 시스템 <-> 이용자, 이용자 <-> 이용자 간에 채팅 기능을 추가한다.
   - 채팅 메시지는 서버를 통해 중계된다.
   - 채팅은 현재의 세션 내에서만 통용되는 것으로 오른쪽 패널을 통해 보여준다.
   - [발신자] 메시지 형태로 보여준다.
   - 채팅 메시지는 세션에 참가한 모든 이용자에게 전달된다.
   - drag & drop 및 파일 업로드 버튼을 눌러 파일을 보낼 수 있다.
   - 채팅 창은 위쪽에 채팅의 내용, 아래쪽에 메시지 입력창이 있고, 그 앞쪽에 파일 업로드 버튼이 있다.
   - 업로드한 파일은 서버에 저장되고, 채팅 메시지에는 파일 다운로드 링크가 포함된다. (서버에 해당하는 기능을 추가)
   - 업로드한 파일은 최대 30일간 유지된다.

3) 메신저 기능
    - 세션이 열려 있건 아니건, 시스템 <-> 이용자, 이용자 <-> 이용자 간에 메시지를 주고 받을 수 있는 메신저의 기능을 추가한다.
    - 메신저 창에는, 오른쪽의 친구아이콘과 메시지 아이콘이 있으며, 친구 아이콘에는 등록된 친구 목록이, 메시지 아이콘에는 최근 주고 받은 메시지 목록이 표시된다.
    - 최근 주고 받은 메시지 목록에서 상대방을 클릭하면, 가운데에 메시지 주고 받는 창이 뜬다.
    - 메시지를 전송 받으면, 전송한 사람과의 메시지 창이 떠 있으면 실시간으로 그 메시지를 메시지 창에 표시한다. 전송한 사람과의 메시지 창이 떠 있지 않고, 메신저 창만 떠 있으면, 메시지 아이콘에 알림 뱃지를 표시한다. 메신저 창도 떠 있지 않으면, 메신저 버튼에 알림 뱃지를 표시한다.

4) PDF를 upload하여 Ncode를 부여하고, server storage 에 등록하는 기능을 추가한다.
    - 호스트는 PDF를 업로드할 수 있으며, 업로드된 PDF는 server storage에 저장된다.
    - PDF를 업로드할 때에는 Ncode의 SOBP(section, owner, book, page)가 부여되며, 이 Ncode는 업로드된 PDF의 각 페이지에 매핑된다.
    - 이를 위해서, 서버에는 PaperHub의 API를 모방하여 구현한다. (NcPaperHubApi라고 칭한다.)
    - NcPaperHubApi에서 SOBP를 할당하는 것은, 이용자 전체에 Unique 한 SOBP가 아니라, 각 이용자별로 Unique한 SOBP로 할당한다. 즉, 5.255.0.0 의 페이지가 이용자별로 다른 PDF의 페이지에 매핑될 수 있다.
    - 따라서 SOBP의 할당을 관리하는 table은 이용자별로 관리되어야 한다.
    - 로컬의 IndexedDB에 PaperHub의 구현체를 구현한 참고 자료는 _Demos/shimizu-demo-2026에 있다. 참고해서 서버쪽 (NeoCAST/Server)에 구현해야 한다.
    - (위의 shimizu-demo-2026을 참고해 보면 nproj도 생성된다) 업로드된 PDF와, 할당된 SOBP, 생성된 nproj, 업로드한 이용자의 4개 정보가 합해진 파일(ncode-pdf compound)을 다른 이용자들에게 채팅 창을 통해 배포할 수 있다.
    - 다른 이용자들은 이 파일을 받아서, 인쇄할 수 있다. 인쇄할 때 실제로 Ncode를 PDF에 입히는 작업은 각 이용자의 PDF에서 실행되도록 한다.
    - 다운로드된 nproj, pdf는 local paperhub의 indexed DB 에 저장한다. 기능 구현은 shimizu-demo-2026을 참고한다.

    - 즉, Client/Web에서의 paperhub의 기능은 다음과 같이 구현된다.
    - Local PaperHub(indexedDB): 호스트 ID와 SOBP를 통해서, nproj와 PDF를 조회하고 저장하는 기능
    - NcPaperHub (NeoCAST PaperHub): 로컬 페이퍼허브에 없으면 NcPaperHub API에 host ID와 SOBP를 넣고, nproj와 PDF를 조회, 저장하는 기능
    - NcPaperHub는 자신이 가지지 않은 SOBP를 요청 받으면 NDP 서버의 PaperHub API를 사용하려, SOBP에 맞는 nproj URL과 PDF url을 전달하는 기능. NDP paperhub api를 통한 NDP로의 저장은 실행하지 않는다.

    - PDF를 upload하고 Ncode가 발행되는 UI, ncode-pdf compound를 가지고 인쇄하는 기능의 UI의 흐름은 _Demos/shimizu-demo-2026을 참고한다.


Server쪽에  blob 을 저장할 수 있는 storage를 연결하려고 한다. 프로덕션 환경에서는 구글의 클라우드를 쓰려고 하는데,

2) 구글 클라우드의 스토리지를 쓸 때, public하게 하지 말고, 필요한 파일을 요청한 경우 서버가 임시 URL을 할당해서 정해진 시간(예를 들면 1시간) 동안만 다운로드 가능하게 하고 싶다.
